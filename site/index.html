How it works

    
It reads only what it needs

    
Most preview data lives in <head>. metagrab streams the page, extracts as it goes, and stops at </head> unless you asked for JSON-LD. Every connection passes a safety check first.


    

      
      
    
        
  1. URL. Validated and checked against your URL policy.
    2. 
        
  2. Safety check, every connection. No private or cloud-metadata IPs, also after redirects and DNS rebinding.
    3. 
        
  3. Read <head>, streaming. Charset decoded, stops at </head>.
    4. 
        
  4. Extract. Open Graph, Twitter, meta, favicon, canonical. Optional JSON-LD and oEmbed.
    5. 
        
  5. metagrab.Link. Absolute URLs, or a FetchError with a code.
    6.

Use it

    
Four ways in

    
Same extractor everywhere. Start with the library; reach for the CLI or the HTTP API when your stack isn't Go.

    

      

        
Go library most common

        
One call with a context and a field mask. Errors are *FetchError with a machine-readable code.

        
client := metagrab.NewClient(
    metagrab.WithTimeout(5 * time.Second),
    metagrab.WithRetries(2),
    metagrab.WithDenyPrivateNetworks(), // URLs from users
)
link, err := client.Fetch(ctx, url, metagrab.PreviewFields)

      

      

        
Parse HTML you have no network

        
From a crawler, a cache or a test fixture. Relative URLs resolve against the page URL.

        
link, err := metagrab.Parse(resp.Body,
    "https://example.com/post",
    metagrab.RichFields) // + JSON-LD
fmt.Println(link.ContentType) // "Article"

      

      

        
CLI

        
JSON to stdout. Several URLs run concurrently. Exit code 2 when any URL fails, for scripts.

        
metagrab https://go.dev
metagrab -fields=rich https://a.com https://b.com
metagrab -compact https://go.dev | jq .title

      

      

        
HTTP API

        
For any language. Private networks blocked by default, API key, JSON logs, graceful shutdown.

        
docker run -p 8080:8080 -e METAGRAB_API_KEY=secret \
  ghcr.io/josephgoksu/metagrab

curl -H "X-API-Key: secret" localhost:8080/fetch \
  -d '{"url":"https://go.dev","fields":111}'

In production

    
Running it behind a product

    
metagrab fetches pages that strangers pick. These six habits keep that boring.

    

      
Block private networksWithDenyPrivateNetworks() whenever URLs come from users. metagrab serve does it by default.

      
Short timeouts3 to 10 seconds, plus a request context so cancelled requests stop fetching.

      
Cache resultsPreviews rarely change. Cache each Link by URL, for example for 24 hours.

      
Key and rate limitSet METAGRAB_API_KEY and rate-limit at your edge. Bound bulk work with WithConcurrency.

      
Retry politelyWithRetries(1-2) covers 429 and 5xx, and respects Retry-After up to a cap.

      
Treat output as untrustedEscape every string. Never inject OEmbed.HTML without a sandboxed iframe.

    

  






  

    
Improve it

    
Make it better with me

    
metagrab is small on purpose: one package, no heavy dependencies, every change measured. Pull requests are welcome.

    

      

        
Get running in a minute

        
git clone https://github.com/josephgoksu/metagrab
cd metagrab
go test -short -race ./...   # unit tests, no network
cd bench && go run .         # benchmarks + charts

        
Read CONTRIBUTING.md and ARCHITECTURE.md first. Keep the API additive, add a test for each fix, and run the benchmarks when you touch the parser. Report security issues privately, as SECURITY.md describes.
